# Hero direction

NMIT's work connects ERP, CRM, payment, mobile, and warehouse systems through an integration layer for banks, exchanges, and insurers. The hero should make that relationship tangible without inventing product metrics.

Three directions considered:
1. An abstract rotating technology orb. Discarded because it communicates nothing specific about integration.
2. A physical architecture workbench: server modules, routed connections, and a central integration stack that visitors can inspect.
3. A typography-led systems readout where the headline changes between the systems NMIT connects.

The implementation combines the architecture workbench with complete animated messages. The workbench has an offset camera and different module heights, reflecting disparate systems rather than identical decorative cards. All other sections remain quiet.

Tokens retain the company's existing design. Light uses sage #EEF0E9, graphite #1B211E, teal #276057 and amber #A5650F: a printed architecture drawing with solid machined modules. Dark uses #14181A, #E8E6DC, muted teal #57B0A4 and amber #E3A24C: a technical inspection bench with brighter connections and darker module faces. IBM Plex Sans carries the explanation; IBM Plex Mono carries system labels and controls. Three-dimensional materials and illumination are tuned separately for each environment. Small amber hero text uses #92590D on light for AA contrast; dark retains #E3A24C. Body, muted, teal, and amber hero text were checked numerically in both modes (minimum 4.5:1).

No decorative particles, glowing background, gradient headline, floating glass navigation, or unsupported claims. The only moving dots represent data traveling along actual system connections. The complete architecture rocks slowly and floats; every headline word animates when its full message changes. Each module opens its own CSS3D-rendered explainer board, attached to the selected system with a 3D connector. Modules are raycast-clickable, and labels and the keyboard-accessible system selector provide the same explanations. Pause stops model motion, data flow, and message changes. Reduced-motion preference disables automatic movement. The original accessible diagram is the fallback when WebGL is unavailable.
